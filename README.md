# RDR2 — путь к 100% и платине

Чек-лист полного прохождения Red Dead Redemption 2: пропускаемое по главам, 100% завершения,
все трофеи, золотые медали за миссии и полный компендиум.

**Открыть:** https://ushckff.github.io/rdr2-100-tracker/

Прогресс сохраняется в браузере (localStorage). Если войти через Google или почту,
он синхронизируется между устройствами через Firebase.

## Структура

| Файл | Что внутри |
| --- | --- |
| `index.html` | разметка страницы, порядок подключения скриптов |
| `styles.css` | всё оформление, включая мобильную версию |
| `store.js` | состояние прогресса: localStorage, слияние, подписки |
| `render.js` | превращает данные в HTML, считает проценты |
| `app.js` | события, фильтры, поиск, меню, экспорт и импорт |
| `firebase-config.js` | публичные параметры проекта Firebase |
| `auth.js` | вход через Google и почту, синхронизация с Firestore |
| `data-guide.js` | вступление, план, разделы глав 1–6 и эпилога с пропускаемым содержимым |
| `data-hundred.js` | чек-лист 100% завершения |
| `data-missions.js` | сюжетные миссии, условия золотых медалей и пропускаемые миссии. Не создаёт свой раздел, а **добавляет группу «Миссии и золотые медали» внутрь глав** из `data-guide.js`, поэтому подключается сразу после него. Отдельно создаёт справочный раздел «Золотые медали» — только правила |
| `data-trophies.js` | 52 трофея, включая онлайн |
| `data-challenges.js` | 90 испытаний |
| `data-compendium.js` | компендиум: животные, рыбы, растения, лошади, оружие, снаряжение, банды, карточки |

## Как добавить или поправить пункт

Все данные — обычные массивы объектов. Каждый файл `data-*.js` добавляет свои разделы:

```js
(window.RDR2_SECTIONS = window.RDR2_SECTIONS || []).push({
  id: "my-section",          // якорь и ключ раздела
  nav: "Название в меню",
  kicker: "надзаголовок",
  title: "Заголовок раздела",
  sub: "Подзаголовок",
  notes: [{ t: "warn", h: "HTML-текст плашки" }],
  groups: [{
    h: "Название группы",
    cnt: "подпись справа",
    items: [
      { i: "uniq-1", t: "Название пункта" },
      { i: "uniq-2", t: "С описанием", d: "пояснение", g: ["miss","tr"] },
      { i: "uniq-3", t: "Счётчик", n: 30 },
      { i: "uniq-4", t: "Со списком требований", r: ["первое", "второе"] }
    ]
  }]
});
```

Поля пункта:

- `i` — уникальный идентификатор, по нему хранится прогресс. **Не менять у существующих пунктов**, иначе отметка потеряется.
- `t` — заголовок, `d` — пояснение, `r` — список требований.
- `g` — метки: `miss` (пропускаемо), `tr` (трофей), `ct` (входит в 100%), `ep` (только после сюжета).
- `n` — если задано, пункт становится счётчиком «сделано из N».
- Текст между `~тильдами~` превращается в спойлер, который открывается кликом.

Порядок разделов на странице = порядок подключения файлов в `index.html`.
Группа раздела в левом меню задаётся картой `NAVGRP` в `render.js`.

Дополнительные поля раздела:

- `spoilerSection: true` — над содержимым появляется кнопка «Раскрыть спойлеры раздела».
- `stat: { prefix, total, label }` — плашка со счётчиком отмеченных пунктов, чей `id` начинается с `prefix`
  (так считаются золотые медали: `prefix: "gm"`).

## Как это ведёт себя на телефоне

При ширине до 1000px включается режим одной вкладки: разделы не идут одной лентой,
а переключаются нижней панелью и боковым меню (`body.single` в `app.js`).
Группы внутри раздела по умолчанию свёрнуты, состояние каждой запоминается в localStorage.
Как только включается поиск или фильтр, режим временно выключается — результаты ищутся по всем разделам.

## Firebase

Проект `rdr2-tracker-a1ce7`. Включены Google и Email/Password, база — Cloud Firestore (регион eur3).
Правила доступа:

```
match /progress/{userId} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
}
```

Прогресс лежит в документе `progress/<uid>` в поле `data`.
При первом входе локальный прогресс объединяется с облачным по принципу «максимум по каждому пункту»,
так что отметки не теряются ни на одной из сторон.
